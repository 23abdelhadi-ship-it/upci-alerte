# 01 — البنية وسير العمل

## المكوّنات

| المكوّن | الدور | الأداة |
|---|---|---|
| نموذج الإبلاغ | واجهة المُبلّغ في العيادات (QR معلّق في المصالح) | Google Forms |
| نموذج الإغلاق | واجهة رئيس(ة) الوحدة لإثبات التدخل (تداول داخلي فقط) | Google Forms |
| المحرّك | المنطق كله: تنبيه، ترقيم، تصعيد، تقارير | Google Apps Script (`apps-script/Code.gs`) |
| السجلّ | سجلّ متابعة مركزي «Suivi UPCI» | Google Sheets |
| التنبيه الفوري | رسائل Telegram + بريد إلكتروني | Bot Telegram + Gmail |
| البوت التفاعلي | استعلامات اختيارية: ‎/stats‏، ‎/critiques‏، ‎/aide | Web App (اختياري) |

## تدفّق بلاغ واحد

```
عون يمسح QR ← يملأ نموذج الإبلاغ (< 60 ثانية، بلا بيانات مريض)
      │
      ▼  زناد onFormSubmit
المحرّك: ترقيم تسلسلي UPCI-AAAA-NNNN ← سطر جديد في السجل (Statut = Ouvert)
      │
      ├── تنبيه Telegram فوري (HTML + رابط السجل)
      └── بريد للمستلمين (رئيس(ة) الوحدة + المشرف)
      │
      ▼  كل 30 دقيقة: verifierCritiquesEnAttente
حرج (Gravité ≥ 4) مفتوح منذ 1 سا ← Relance 1h
حرج مفتوح منذ 4 سا ← Escalade 4h (موسومة)
      │
      ▼  نموذج الإغلاق (رقم البلاغ + التدخل المنجز)
المحرّك يُحدّث السطر نفسه: Statut = Clôturé، Date clôture، Durée (h)
      │
      ▼  فاتح الشهر 08:00 — rapportMensuel
تقرير CLIN يُرسل بالبريد: الحجم، % الحرج، % الإغلاق، متوسط أجل الإغلاق
```

## الزنادات (Triggers)

| الزناد | النوع | التوقيت |
|---|---|---|
| `onFormSubmit` | إرسال نموذج (×2: إبلاغ وإغلاق) | فوري |
| `verifierCritiquesEnAttente` | زمني | كل 30 دقيقة |
| `rapportMensuel` | زمني | فاتح الشهر، 08:00 (Africa/Algiers) |

## قواعد مدمجة جديرة بالذكر

- **الترقيم بقفل (LockService):** لا تصادم أرقام مهما تزامنت البلاغات.
- **مضادّ التكرار:** نفس الردّ يُرسل مرتين خلال 3 دقائق → الثاني يُهمل.
- **مطابقة مرنة للحقول:** تغيير طفيف في عنوان سؤال بالنموذج لا يكسر السلسلة
  (مقارنة مُطهَّرة من الأكسّان والحالة).
- **الأسرار في Script Properties فقط:** رمز البوت وقوائم المستلمين تُضبط بـ `configurer()`
  ولا تظهر في الشيفرة.
- **تنبيه المشرف عند الخطأ:** أي فشل تنفيذ يُبلَّغ آليًا لبريد الإدارة.
