# نظام الإنذار الرقمي UPCI — الطبعة المحمولة JavaScript (Édition Portable)

## Système d'alerte numérique UPCI — Signalement → Alerte → Clôture → Bilan

**شيفرة واحدة، بيتان.** هذه الطبعة مكتوبة بلغة JavaScript وفق معايير الويب
(Request/Response)، وتشتغل **دون أي تغيير في منطق العمل** في بيتين اثنين:

| البيت | التشغيل | قاعدة البيانات | المهام الدورية |
|---|---|---|---|
| **Cloudflare Workers** | `wrangler deploy` | D1 (SQLite سحابي) | Cron Triggers (كل 30 دقيقة) |
| **خادم المؤسسة المحلي** | Node.js ≥ 20 | ملف SQLite محلي | مؤقّت داخلي كل 30 دقيقة |

الفصل بين المنطق والمنصة يتم عبر طبقة توافق رقيقة: نقطتا دخول فقط
(`worker.js` و`server.mjs`) ومهايئ قاعدة بيانات واحد بنفس لهجة SQL،
وكل الباقي مشترك في `src/`.

## كيف يعمل؟ (30 ثانية)

1. العون الصحي يمسح رمز QR في العيادة ويجيب عن 9 أسئلة مغلقة (أقل من دقيقة،
   **لا بيانات مرضى إطلاقًا**).
2. يُسجَّل البلاغ برقم تسلسلي `UPCI-2026-0001` وينطلق تنبيه فوري إلى مسؤولة
   وحدة UPCI عبر Telegram (مع زر «✅ تم الاستلام») والبريد إن كان مهيأً.
3. الحالات الحرجة (خطورة ≥ 4) تُتابَع آليًا: تذكير بعد ساعة، تصعيد بعد 4 ساعات،
   تنبيه عند غياب الاستلام، وتجميع مشتبه عند تكرار نفس النوع في نفس العيادة.
4. الإغلاق من صفحة داخلية بمفتاح: تدخّل، إجراء تصحيحي، ثم تحقق من الفعالية
   بعد أيام — حلقة تعلّم كاملة، ويصل المُبلِّغَ بريد «عولج وأُغلق».
5. تقارير جاهزة: حصيلة CLIN شهرية قابلة للطباعة، ونشرة «بلّغتم ← غيّرنا»،
   ومراقبة أسبوعية للعيادات الصامتة ونبض سلامة للنظام نفسه.

## التركيب دون لمس أي ملف شيفرة

عند أول تشغيل، يفتح النظام تلقائيًا صفحة **`/installation`**: اسم المؤسسة،
العيادات، بريد التنبيهات، بوت Telegram، عتبات التصعيد، كلمة سر الإدارة
ومفتاح صفحة الإغلاق — مع زرَّي اختبار فوري (Telegram وبريد). تُحفظ الإعدادات
في قاعدة البيانات نفسها، ثم تُقفل صفحة التركيب نهائيًا وتنتقل الإعدادات
إلى **الإدارة ← الإعدادات** (`/admin/reglages`). لا أسرار في الشيفرة أبدًا،
والبوت لا يُعاد عرضه بعد حفظه.

## محتويات المشروع

```
worker.js            نقطة دخول Cloudflare Workers (fetch + scheduled)
server.mjs           نقطة دخول Node.js (HTTP + SQLite + مؤقّت داخلي)
wrangler.toml        إعداد Cloudflare (ربط D1 + كرون) — بلا أسرار
schema.sql           مخطط القاعدة (لتهيئة D1 عبر wrangler)
.env.example         نموذج متغيرات البيئة لخادم المؤسسة
src/
  app.js             الموجّه وكل الصفحات (نفس المنطق للبيتين)
  metier.js          إنشاء، استلام Telegram، إغلاق، إعادة فتح
  cron.js            runPeriodicChecks() — تصعيدات، تجميع، صمت، حصيلة
  rapports.js        حصيلة CLIN + نشرة «بلّغتم ← غيّرنا»
  reglages_page.js   صفحتا /installation و /admin/reglages
  settings.js        قراءة إعدادات قاعدة البيانات عند كل تشغيل
  notify.js          Telegram + بريد (API HTTPS اختيارية)
  db.js              مهايئ D1 / node:sqlite + مخطط القاعدة
  seed.js            بيانات العرض التجريبي (إنشاء/سحب)
cli/                 init، seed_demo، purge_demo، cron، hash (لبيت Node)
```

## نموذج الأمان

- لا بيانات مرضى بالتصميم: أسئلة مغلقة فقط، ولا حقل نص حر في نموذج الإبلاغ.
- Telegram قناة تنبيه فقط: لا يحمل إلا ملخصًا تشغيليًا بلا أي معطى حساس.
- صفحة الإغلاق بمفتاح وصول، والإدارة بكلمة سر (بصمة PBKDF2 في القاعدة)،
  وجلسات موقعة HMAC، وسجل تدقيق بإضافة فقط لا يُمحى.
- الأسرار لا تظهر في الشيفرة ولا تُعاد كتابتها في الصفحات بعد الحفظ.

## التركيب في سطرين

- **Cloudflare:** `npx wrangler d1 create upci` ثم `npx wrangler deploy`،
  وبعدها افتح `/installation`.
- **خادم المؤسسة:** انسخ المشروع، `node server.mjs`، وافتح `/installation`.

التفاصيل الكاملة (D1، الأسرار، webhook، الخدمة الدائمة، النسخ الاحتياطي،
وملاحظة الشبكة المحلية): انظر **INSTALL.md**.
